# Agent 自动接入与后台证书更换实施计划

目标：用户执行后台安装命令即可自动生成节点私钥、回传 CSR、取得证书并建立联系；后台可请求现有 Agent 轮换证书。公开注册 origin 为 https://console.reladock.com，注册必须与签发凭证的数据库一致。

沿用 Go/PostgreSQL、现有 bootstrap token、mTLS、两阶段轮换和持久身份目录。安装默认 validation-only，不自动修改转发网络。CA 初始化只适用于全新托管目录；已有 PKI、未知安装状态、WAL 和 journal 不允许覆盖或清空。人工证书管理继续保留。

- [x] 控制端：提供受保护的自动 PKI 初始化及明确的配置就绪信息，保留已有人工 CA 优先级；使用固定 Release，不跟随 latest。
- [x] 轮换：平台管理员按 revision 请求，数据库持久保存针对当前证书的请求；Agent 主动查询并复用现有两阶段流程；旧 Agent 可继续正常运行；实际激活后才能报告完成。
- [x] 界面：安装入口、自动更换、手工证书管理分别提供；错误、等待与成功如实区分。
- [x] 专项验证：随机 PostgreSQL schema 中权限/审计回滚/重放/旧证书请求隔离；Agent 未到期受控轮换、断线恢复；PKI 持久复用/拒绝不完整状态；真实 mTLS 与 Linux PKI 测试通过。全量测试仍有既有成本和历史迁移失败，见 IMPLEMENTATION_STATUS.md。
- [x] 本地部署：用户明确选择继续本地测试，不改线上。已备份并更新本地 3012/schema v33，保留 HTTP 开发监听；未启用远程 VPS 安装，不把本地 token 指向线上数据库。
- [ ] 后续另行部署：发布新版 Agent 固定包、配置可达 HTTPS 和实际 VPS 安装验收；不属于本次用户选定的本地测试交付。

风险检查：重启不重建 CA；并发启动不覆盖；手工撤销/轮换后旧请求失效；安装包必须为真实固定发行版本；离线/旧版 Agent 不虚报轮换完成。
