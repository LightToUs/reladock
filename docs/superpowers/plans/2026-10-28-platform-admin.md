# Platform administration Implementation Plan

> **For agentic workers:** Execute inline using executing-plans. 用户明确要求实现全平台管理，直接开发，不等待方案审批。当前非 Git 目录，不初始化仓库。

**Goal:** 交付可实际操作的全平台后台，区别于企业租户控制台。

**Architecture:** v3 迁移添加独立平台权限、企业登录状态、节点修订号及元数据、平台审计。后端每次核验数据库平台权限，所有管理写入与平台审计同事务，使用平台授权锁和节点锁；浏览器 /admin 使用现有会话，提供节点维护、企业管理、全局规则、交付与审计。

**Tech Stack:** 现有 Go、PostgreSQL、静态 HTML/JS/CSS。

**Spec:** AGENTS.md、docs/REQUIREMENTS.md、docs/ARCHITECTURE.md、docs/ROADMAP.md；用户明确要求全平台管理。

## Global Constraints

- owner 不是平台管理员；注册、请求体、前端状态均不能授予平台权限。
- 权限授予/撤销仅本机运维 CLI，撤销已有会话；显式为 admin@reladock.local 开通，不重置密码。
- 仅回环监听，不采购节点、执行真实防火墙、公开发布或接真实支付。
- 校验 Agent 不代表生效；不伪造钱包、用量、健康、账单。
- 修改和证书轮换包含修订号校验；有规则时不能更换绑定地址；节点声明速率低于已有规则上限时拒绝。

## Review Focus

- 普通 owner、伪造管理员标志、撤销后的旧身份必须拒绝跨租户管理。
- 平台审计失败必须回滚节点、规则、队列及企业状态。
- 节点修改并发/旧版本、证书轮换、配置重试不能覆盖新修改。
- 企业停用立即撤销会话，不能停用含平台管理员的企业，也不宣称停止数据面流量。
- 管理列表分页、证书仅公钥 PEM、字段限制、原数据升级与两端界面隔离。

## 交付与验证记录（2026-10-28）

- 28 个 Go 顶层测试与 2 个前端测试通过，`npm test` 包含真实 PostgreSQL、TLS/Agent、HTTP 集成与 Go 竞态检测；`npm run vet` 和前端语法检查通过。
- 独立只读复查发现退出登录与企业停用/平台授权之间的锁顺序反转。使用数据库触发器与锁屏障稳定复现两条路径的 SQLSTATE 40P01；Logout 改为先取授权锁，再操作 session，两个并发回归及全套测试通过。
- 管理表单遇到 409 时载入最新修订资料，避免无限重试旧版本。节点证书绑定与撤销、平台规则/企业操作的审计失败回滚已补充集成覆盖。
- 自动审批初次拒绝向具体本地账号提权，要求明确授权；用户随后明确选择“授权为该账号开通全平台权限”。获授权后 CLI 已开通 admin@reladock.local，密码不变，旧会话撤销。
- 浏览器实际验证管理员登录、节点新增、编辑、公网 IP 元数据、维护/恢复、交付重试、历史状态与操作人审计。仅操作 ui-admin-check 临时节点；已按精确标识与名称、无规则/端口/证书条件清理该节点，保留平台审计，未主动修改用户原有节点或规则。
- 独立 /admin 标签已保留，管理员登录可用。服务继续仅监听 127.0.0.1:3001；未执行真实网络规则、采购、公开部署或收款。
- 决策：权限授予仍只提供本机 CLI；后台企业停用只限制登录和控制面，不能宣称停止已存在的数据面流量。
- 决策：保留原有企业工作台与严格租户范围，平台规则操作只记平台身份；节点维护恢复仍显示尚未部署。
- 后续未实现：实际转发与健康、计量账务支付、成员邀请/API Key、生产证书与外部防篡改审计、规模验收；没有做虚构统计或状态。
