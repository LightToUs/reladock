# Production readiness implementation plan

> 用户要求直接实现功能，服务器、域名和支付渠道之后确定。继续在当前目录开发；当前不是 Git 仓库，不自动初始化。使用 executing-plans 与独立子任务并行实施，所有生产声明依赖实测。

**Goal:** 补齐首期商业中转平台，提供可安装、可验证的部署路径；未完成验收不得标记生产就绪。

**Architecture:** 延用 Go + PostgreSQL。账务与授权以数据库事务为边界，节点通过独立 mTLS 通道联系；Linux 数据面与本机开发环境隔离。公网访问通过明确 HTTPS origin 与 TLS 配置。

**Spec:** AGENTS.md、README.md、docs/REQUIREMENTS.md、docs/ARCHITECTURE.md、docs/ROADMAP.md 及当前用户明确指令。

## Global constraints

- 不购买/发布资源，不接入真实收款，不修改实际主机网络规则。
- USD 整数金额、不可变账本、重复事件幂等；无实际采集不展示消费。
- 最新明确要求：流量按规则独立累计、额度与扣减，不共享企业流量池；企业钱包可支付多条规则但账单明确关联规则。
- 无 applied ACK 与健康验证不显示运行中；UDP 未知明确为未知。
- 生产机器、域名、支付渠道由用户之后决定，不将默认值当成确认需求。

## Review focus

- 代理请求头伪造、HTTPS Cookie、错误 origin 与配置回退。
- 撤权与并发请求、API Key 不能升级为平台管理员。
- 重复及乱序用量、计数重置、并发账务与跨企业访问。
- 非平台防火墙配置保护、受控应用、回滚和版本拒绝。
- Linux 内核行为、实际支付和生产恢复只能通过对应环境验收。
