# 未绑定企业专属节点自动认领设计

## 已确认目标

平台新增“企业专属资源”节点时，专属企业可以留空。此时节点处于“待分配”状态，可被线路商品和套餐引用，但还不属于任何企业。某企业第一次成功购买该节点对应套餐时，节点才永久绑定到该企业。

本设计只适用于 `dedicated-tenant`。共享资源不绑定企业；规则专属资源继续要求预先绑定企业并保持一条未删除规则的独立约束。

## 业务语义

- 新增或编辑未绑定的企业专属节点时，`dedicatedTenantId` 可为空；后台显示“待分配 / 首次成功购买后绑定”。
- 创建支付订单、进入收银台、支付失败或未支付都不占用节点。
- 只有套餐购买事务真正成功时才认领节点。钱包扣款、订阅/权益创建、节点归属和审计必须在同一个数据库事务提交或一起回滚。
- 多个企业并发购买同一待分配节点时，事务先锁定节点；第一个成功提交的企业获得节点，其他企业收到明确的“该企业专属节点已被其他企业认领”，不得扣款或创建权益。
- 已绑定节点只能由绑定企业继续购买或创建规则。目录和购买接口都必须在服务端重新校验归属，不能只依赖前端隐藏。
- 退款、争议、套餐到期或规则删除不自动解绑节点。
- 释放归属只能由平台管理员显式发起，并要求节点无活动订阅、无未删除规则、无活动端口分配或未完成端口回收、无未完成配置交付；操作按节点修订号保护并写平台审计。

## 数据与并发边界

schema v43 只放宽 `nodes_resource_mode_owner_check`：`shared` 仍禁止企业归属，`dedicated-rule` 仍强制企业归属，只有 `dedicated-tenant` 可以为空。购买路径沿用节点 advisory lock，并在任何钱包扣款之前重新读取归属；真正的归属更新推迟到购买落库阶段，因此报价和支付订单不会占用资源，购买失败也会随事务回滚。

认领会递增节点 `revision` 并写 `node.dedicated-claim` 平台审计；人工释放会递增同一修订号并写 `node.dedicated-release`。绑定后的普通节点编辑不得绕过释放门禁直接清空或替换企业。

## 必需验证

- schema v42→v43 保留既有绑定并只允许企业专属节点为空。
- 待分配企业专属节点可由平台管理员创建、编辑和发布线路；规则专属节点仍拒绝空企业。
- 未绑定套餐对所有企业可见；首次钱包购买原子绑定，余额不足、审计失败和落库失败均不留下归属或扣款。
- 两企业并发购买只有一个成功；失败方余额、账本、订阅和幂等结果保持不变。
- Stripe 报价/订单不绑定；验签支付回调只有购买成功才绑定，已知购买失败只保留到账资金。
- 同企业幂等重试返回同一购买结果，不重复扣款、认领或审计。
- 已绑定节点不出现在其他企业目录，直接购买也被拒绝；规则创建仍要求节点已归属当前企业。
- 人工释放前置条件、修订冲突、越权和审计回滚完整覆盖。

## 生产边界

生产当前为 schema v42 且业务节点、规则、线路、套餐、订阅和账本均为空。发布应先恢复生产备份到临时数据库演练 v42→v43，再停服生成即时备份、替换控制二进制并迁移。此功能只改变控制面资源归属和销售准入，不购买服务器、不修改 Agent、nftables/tc、客户流量或端到端健康状态。
