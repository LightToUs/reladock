# 网络中转工作台可观测性设计

## 目标

让企业在网络中转工作台直接看到本企业每条转发规则的累计上下行流量、最近上报速率、相对该规则带宽上限的利用率，以及 1 小时、24 小时、7 天的用量趋势；同时显示这些规则实际使用的入口节点的最新 CPU、内存、根磁盘和 conntrack 样本。

平台继续区分配置交付、Agent 联系、资源样本、计量报告和端到端业务健康。任何缺失、过期或无法可靠推导的数据都显示未知，不用 0 代替。

## 数据口径

- 累计流量来自现有 `billing_usage_totals`，按规则分别展示上行、下行及合计，不建立企业共享流量池。
- 最近速率使用同一规则、同一计量 epoch 的最后两份已接受报告计算。只在最新报告不超过 30 秒、报告间隔为 1–60 秒时展示；否则返回 `insufficient` 或 `stale`。
- 速率属于“平台最近接收速率估算”，不是链路瞬时带宽或 SLA。利用率以该规则配置的 `bandwidth_mbps` 为分母，可超过 100% 以暴露采样或整形异常，不做静默截断。
- 趋势使用不可变 `billing_usage_reports` 的 delta，按平台接收时间聚合。1 小时使用 1 分钟桶，24 小时使用 15 分钟桶，7 天使用 2 小时桶。空桶表示没有已接收报告，不推断为零流量或健康。
- 节点资源复用现有 `node_resource_latest`。企业只可读取仍被本企业未删除规则引用的节点；样本超过 90 秒显示过期。平台后台继续保留全节点视图。

## 接口与权限

- `GET /api/billing/telemetry` 返回本企业未删除规则的累计流量和最近速率摘要。
- `GET /api/billing/telemetry?ruleId=<uuid>&window=1h|24h|7d` 返回该规则的摘要与稀疏趋势点。
- 现有 `GET /api/billing/usage?ruleId=<uuid>` 保持兼容。
- `GET /api/operations/nodes` 扩展最新资源字段，不增加企业可见节点范围。
- 所有查询继续在 PostgreSQL 中重新核验当前成员、企业状态和租户归属；跨租户规则返回未找到。

## 工作台交互

- 规则列表刷新时自动加载累计流量与速率，不再要求点击“查询本规则”。
- 新增独立“流量与节点资源”区：可选择规则与时间窗口，展示累计流量、最近上下行速率、带宽利用率、稀疏趋势和口径提示。
- 入口节点资源以紧凑卡片呈现数值、状态与采样时间；未知和过期使用明确文案。
- 页面手动刷新会同时刷新规则、计量和资源。趋势切换只读取选择的规则和窗口。

## 非目标

- 不把接收时间聚合描述为数据面精确发生时间。
- 不新增 Prometheus/Grafana、长期节点资源时序或端到端协议探针。
- 不改变 Agent 计量 WAL、账务去重、套餐扣减、网络规则或 tc 带宽上限。
- 不向企业暴露其他租户规则、未关联节点或平台级成本数据。
