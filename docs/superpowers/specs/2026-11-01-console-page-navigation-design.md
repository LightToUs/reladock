# 控制台分页导航设计

## 目标

企业工作台与平台管理后台不再把所有功能纵向堆叠在同一页面。每个菜单项对应一个独立视图和可复制的 URL 状态；侧栏可在桌面收起为窄栏，在移动端作为抽屉打开。

## 交互

- 企业工作台使用 `#/overview`、`#/rules`、`#/traffic`、`#/node-status`、`#/delivery`、`#/billing`、`#/team`、`#/operations`。
- 平台后台使用同样的 `#/view` 形式，包含现有全部动态菜单。
- 切换视图只显示当前视图的内容，保留同一页面内已加载的数据、弹窗和登录会话。
- 浏览器前进、后退和直接打开 URL 都能恢复对应视图；未知地址回退到总览。
- 桌面侧栏收起状态保存到本机；收起后仍保留可辨识的图标和无障碍名称。
- 移动端菜单由页面顶栏按钮打开，选择菜单或按 Escape 后关闭。

## 页面分组

- 企业总览：运行摘要、流量路径说明、运行边界和最近操作。
- 企业协作：成员、邀请、API Key 和一次性令牌结果。
- 其他企业菜单各自对应现有单一业务区。
- 平台后台继续沿用现有 pane 分组，只增加 URL 路由和桌面收起能力。

## 边界

- 不改变 API、数据库、Agent、权限和计量逻辑。
- 不打开新浏览器标签；“新的页面”指独立视图与独立 URL，可直接打开、收藏和前进后退。
- 自动刷新继续运行；页面切换不伪造健康状态，也不清空最近成功数据。

## 验收

- 两个后台任一时刻只显示当前菜单对应内容。
- URL、选中菜单、页面标题始终一致。
- 桌面可收起/展开，刷新后保持；移动端可打开/关闭且焦点可恢复。
- 既有功能测试、完整测试和静态检查通过，并提供本地测试地址。
