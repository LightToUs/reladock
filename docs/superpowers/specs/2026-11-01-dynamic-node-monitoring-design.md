# 动态节点监控与蓝色控制台设计

## 目标

RelaDock 的平台管理员与企业客户都需要在日常工作页面直接看到入口节点的动态运行数据，而不是依赖手工刷新或把节点资源藏在规则遥测区域。页面必须继续区分控制面事实、资源事实与端到端业务健康。

## 平台管理员体验

“全部入口节点”保留现有管理列表和操作能力，在每个节点项中追加动态监控区域：近期上行/下行速率、累计上行/下行流量、CPU、RAM、根磁盘、conntrack、Agent 运行时长和数据更新时间。管理员数据覆盖该节点上的全平台规则，但不展示客户业务载荷。

动态更新只替换监控数值，不重新创建管理按钮、关闭对话框或打断正在进行的节点操作。

## 企业体验

企业工作台导航新增“节点状态”菜单和独立节点状态区域。只显示与当前企业未删除转发规则关联的入口节点。节点共享资源指标可以展示，但流量与速率只汇总当前企业在该节点上的规则，禁止泄露其他企业数据。节点状态区域可以列出关联规则数量，但不暴露其他企业规则。

## 数据语义

- 累计流量来自已接受、已去重的逐规则计量总数，按节点汇总。
- 近期速率沿用平台接收时间差值估算：同一 epoch 最近两个报告间隔必须为 1–60 秒，最新报告不超过 30 秒。
- 节点有至少一条新鲜规则速率时，显示这些新鲜报告的速率合计；没有新鲜速率但存在旧报告时显示“已过期”；只有单个近期样本时显示“计算中”；从未收到报告时显示“尚无流量报告”。未知状态不能显示为零。
- CPU、RAM、根磁盘、conntrack 与数据面一致性来自 Agent 最新资源样本；超过 90 秒显示“数据已过期”。
- “在线”只表示近期 Agent 心跳；`in-sync` 只表示本地数据面检查一致；两者均不表示 VPN、代理协议或客户端端到端健康。
- 页面显示的是 Agent 运行时长，不声称是 VPS 系统开机时长。

## 刷新行为

页面使用递归定时轮询，不使用 WebSocket：可见页面每 5 秒读取节点监控数据；页面隐藏时降为每 30 秒；重新可见时立即刷新。请求不能重叠。失败时保留最后一次成功值并标记更新时间/更新失败；认证失效仍交由现有登录流程处理。

## 视觉

平台管理员后台和企业工作台统一为蓝色主视觉。管理员后台采用浅蓝画布、深蓝导航和蓝色操作强调；企业工作台采用深海军蓝画布、蓝色导航与亮蓝强调。告警继续使用红/橙色，明确在线状态可以使用绿色，不能因主题统一而丢失状态语义。公开官网不修改。

节点监控使用紧凑的数值、进度条和更新时间表达，桌面端适合高密度运维；窄屏允许横向滚动或卡片重排，页面本身不得产生横向溢出。

## 边界

- 不新增长期 CPU/内存/磁盘时序存储。
- 不把展示速率用于计费、配额或 SLA。
- 不升级或修改入口 Agent、nftables、tc、路由或转发规则。
- 不引入新前端框架或 WebSocket 基础设施。
- 本轮只发布控制端；生产部署仍保留备份、摘要、服务和公网验证步骤。
