# Agent 长期运行可靠性设计

## 目的

借鉴 FRP、Rathole 等长期运行网络组件的连接恢复和身份轮换机制，补齐 RelaDock Agent 在控制台短时不可用、节点重启和 30 天证书到期时的自动恢复能力。继续使用现有 Go Agent、PostgreSQL 控制面和 nftables/tc 数据面，不引入第三方隧道作为默认转发底座。

本次只修改控制通道和节点身份生命周期。它不改变已应用转发规则，不把控制通道在线、配置 applied 或目标 TCP 可达误称为端到端健康，也不自动部署到现有服务器。

## 目标

- 控制台或网络短时不可用时，Agent 自动退避重连，恢复后继续配置、计量、探测和环境报告。
- 节点证书在到期前自动续签，不要求管理员每 30 天重新安装 Agent。
- 续签在请求或响应丢失、Agent 重启、控制服务多实例及重复请求下保持幂等，不能让旧证书和新证书同时失效。
- 管理后台分别显示控制通道联系、证书状态、配置状态和已有探测结果。
- 失败保持 fail-closed：不能通过清理 Agent journal、WAL、PKI 轮换状态或数据库 applying 屏障来恢复。

## 非目标

- 不替换 nftables/tc，不部署 FRP、GOST、Rathole、NPS 或 Realm。
- 不实现 VPN 协议终结、订阅、UUID、密码或终端用户管理。
- 不把心跳、续签成功、applied ACK 或 TCP 目标可达当作端到端转发健康。
- 不实现 Agent 二进制自动升级、CA 自动轮换、跨版本滚动部署或遗失私钥后的无人值守恢复。
- 不修改生产节点网络设置，不自动发布 GitHub Release。

## 总体方案

### 1. 自适应控制循环

把 `cmd/reladock-agent` 中固定 5 秒循环抽成可测试的 Supervisor：

- 正常领取到 204、成功回报或无待处理任务都视为控制连接成功，并恢复 5 秒正常轮询。
- 控制请求失败后采用带随机抖动的指数退避，基础 1 秒，上限 60 秒；成功一次立即清零失败次数。
- 配置应用的不确定结果仍由现有持久 journal 和 applying 屏障处理；退避器不得清理或改写这些状态。
- 用量 WAL、探测和只读环境报告继续独立保留错误；本地采集不能因为控制端暂时不可用而停止。
- 进程收到退出信号时立即取消等待，不为退避延迟关机。

配置领取、心跳、用量上传、探测、环境报告和证书续签分别维护退避状态。某个非关键活动失败不能推迟配置领取或用量落盘；同一网络故障可能让多个活动各自退避，但都必须使用抖动且受现有节点速率限制约束。随机源和时钟通过小接口注入，测试使用确定性值；生产不增加外部依赖。

### 2. 明确的 Agent 心跳

新增受现有 mTLS 精确证书身份保护的 `POST /agent/heartbeat`。Agent 正常运行时每 30 秒报告一次有限元数据：版本、运行模式（validation/apply）、本次进程启动时间、当前证书到期时间、轮换状态和有限轮换错误码。错误码只允许预定义的 `state-invalid`、`key-mismatch`、`certificate-invalid`、`publish-failed`、`renew-unavailable` 和 `activate-unavailable`；不得上传业务载荷、私钥、主机凭据或完整错误文本。

心跳事务再次核对节点当前或允许激活的证书指纹，并更新节点最近联系、Agent 版本、模式、启动时间和证书到期时间。后台状态口径：

- 90 秒内有心跳：在线。
- 从未有心跳：从未连接。
- 超过 90 秒：离线，页面可提示“Agent 会自动重连”，但不声称已确认正在重连。
- 维护状态单独显示，不覆盖最近联系事实。

现有配置状态、探测状态和 applied generation 继续单独展示。

### 3. 两阶段证书续签

证书仍为 30 天有效期。Agent 在剩余 7 天以内开始续签；失败使用控制循环的退避策略重试，不等到证书临近失效才首次尝试。

续签分为签发和激活两阶段：

1. Agent 在私有 PKI 目录生成新的 Ed25519 私钥和 CSR，并先持久化轮换记录。
2. 使用当前有效证书调用 `POST /agent/certificate/renew`。
3. 控制端在节点事务锁下验证当前指纹，签发同一节点身份的新证书，把 CSR 摘要、证书、待激活指纹和时间保存到独立轮换记录；节点当前指纹暂不改变。
4. 同一 CSR 的重复请求返回同一证书。存在尚未解决的不同 CSR 时返回冲突，不静默覆盖。
5. Agent 验证新证书的节点 URI、用途、有效期、CA 链和本地私钥匹配后，以新证书调用 `POST /agent/certificate/activate`。
6. 激活事务只接受当前待激活指纹；成功后原子提升为节点当前指纹并使旧指纹失效。相同新指纹重复激活返回成功，解决“服务端已提交但响应丢失”。
7. Agent 收到成功或用新证书确认服务端已经激活后，原子发布新的本地身份并关闭旧连接。

控制端只允许一个未解决轮换。轮换状态不随普通租约超时自动清除；管理员以后可增加显式修复工具，但本次不提供会绕过身份核对的网页按钮。

现有手工证书登记、撤销以及新的 bootstrap 兑换必须在同一个节点事务中取消并删除该节点未激活的轮换记录。被取消的待激活证书随后不得激活；人工操作后的新当前指纹是唯一可信身份。取消动作写平台审计，但不清理 applying 屏障、Agent journal 或计量状态。

### 4. 本地凭据原子性与重启恢复

现有安装使用分开的 `agent.crt` 和 `agent.key`。为避免轮换时只替换其中一个导致重启失败，引入权限为 0600 的单文件身份包，内容仅包含证书链和对应私钥，通过临时文件、`fsync` 和原子重命名发布。

- 新安装同时生成身份包；旧安装在首次成功续签后迁移，原文件不被覆盖或删除。
- 当前身份包与待激活身份包分开保存，轮换状态记录所处阶段和 CSR 摘要。
- 启动时若发现待激活记录，优先继续同一轮换，不生成第二把密钥。
- 如果服务端已经激活但本地尚未发布，Agent 使用持久化的新身份重复激活并完成本地发布。
- 如果本地私钥、轮换记录或身份包缺失/不匹配，Agent 停止自动续签并报告明确错误；不删除 PKI 目录，也不回退到不受信身份。

TLS 客户端通过受锁保护的凭据管理器读取当前身份；成功激活后切换新身份并关闭空闲连接，后续请求使用新证书。

### 5. 数据模型、告警和后台

新增迁移保存 Agent 心跳字段和每节点最多一条待激活证书轮换记录。证书正文仅保存在受限数据库记录中用于幂等恢复，不通过后台列表返回；平台审计只记录节点、动作、时间和非敏感状态。

后台节点列表新增：

- 控制联系：在线、从未连接、离线。
- Agent：版本、validation/apply 模式。
- 证书：正常、7 天内到期、已过期、正在轮换、轮换异常。
- 配置：保持现有待领取、validated、applying、applied、failed 语义。
- 探测：保持 TCP 目标可达/不可达和 UDP unknown，不增加“运行中”结论。

运营对账新增可去重事件：证书 7 天内到期、证书已过期、轮换持续失败。相同非空轮换错误码连续存在 1 小时定义为“持续失败”；短暂错误只在节点详情保留最新状态，不立即发通知。成功轮换或连续心跳恢复为 `idle` 后解除对应事件；通知继续走现有 Outbox，不直接从 Agent 发外部消息。控制端无法联系节点时只能依据最后心跳和已知证书到期时间告警，不猜测本地错误原因。

## 运行配置

续签复用现有节点签发 CA，但签发器能力与 GitHub Release 元数据在代码中分开。开发环境可仅启用 mTLS Agent 通道而不启用续签；此时心跳和配置功能照常工作，节点详情明确显示 `renew-unavailable`。

生产环境只要启用 mTLS Agent 通道，就必须提供可用的节点 CA 证书、私钥和信任链，否则控制服务拒绝启动。Release 版本和摘要仍只决定 bootstrap 安装命令是否可用，不决定续签能力。CA 自动轮换不在本次范围；现有“签发 CA 至少剩余 31 天”的启动检查继续保留。

## 安全边界

- 续签端点只在 mTLS Agent 监听器开放，浏览器会话、API Key 和 bootstrap token 均不能调用。
- CSR 必须是 Ed25519、签名有效、无自带身份扩展；服务端重新写入固定 `spiffe://reladock/nodes/<id>`。
- 当前证书必须尚未过期且指纹与数据库精确匹配，才能创建待激活证书。
- 激活端点只接受待激活新证书或已经提升的同一证书，不允许任意登记证书。
- 手工登记、撤销或 bootstrap 换证后，先前待激活证书永久失去激活资格。
- 私钥只在节点生成和保存，控制端永远不接收私钥。
- 续签、激活、心跳均受现有节点速率限制、请求大小限制、TLS 1.3 和事务节点锁保护。

## 测试与验收

单元和 PostgreSQL 集成测试至少覆盖：

- 退避随连续失败增长、封顶、带抖动，任意成功后重置，取消立即退出。
- 心跳身份不匹配、旧证书、非法模式/版本/时间被拒绝；90 秒状态边界准确。
- 同 CSR 重复续签返回同一结果；不同 CSR 冲突；多实例并发只产生一个待激活结果。
- 续签响应丢失后可恢复；激活响应丢失后新证书重复激活成功；激活后旧证书立即失效。
- Agent 在签发前、签发后、激活后、本地发布前各阶段重启都能继续，不覆盖当前可用身份。
- 身份包截断、权限错误、证书和私钥不匹配时 fail-closed。
- 证书即将到期/已过期事件去重、解除和复发；后台不泄露证书正文、CSR 或私钥。
- 现有配置 journal、applying 屏障、WAL、逐规则计量和探测测试继续通过。

完成代码与本地测试不等于生产验收。上线前仍需在隔离 VPS 演练控制台中断、Agent 重启、响应丢失和真实证书轮换，并验证旧证书撤销、新证书持续运行及用量 WAL 无缺口。

## 实施拆分

这是一个项目级改造，按依赖顺序拆为四个可独立审查的部分：

1. Supervisor 退避循环与明确心跳。
2. 控制端两阶段续签事务和数据库迁移。
3. Agent 本地凭据管理、续签状态机与重启恢复。
4. 后台状态、告警、文档和完整回归。

实现细节遵循现有 Go/PostgreSQL 结构，不引入 Redis 或新的运行时依赖。版本号、发布 tag 和生产部署不在本设计内，由完成验证后的单独发布步骤决定。
