## 节点安装接入（v18）

2026-11-07 托管与主动轮换增量：NODE_MANAGED_PKI_DIR 显式启用全新控制端的持久根/中间签发器/服务端身份初始化，不能与人工 PKI 混用，不覆盖未知状态；数据库已存在身份历史而目录丢失时拒绝创建新根。v33 请求保存当前 certificate_fingerprint，只有平台授权、revision 和能力门禁通过才写入，并与审计同事务。Agent 通过 HTTP 能力头兼容旧控制端，心跳回复携带目标指纹；Agent 仅对自身当前指纹唤醒轮换。既有 rotation.json 继续承担请求/激活恢复，旧响应不能让新身份再轮换。身份替换通过数据库触发器清除旧请求及能力，能力需新身份心跳重新证明。
控制台 HTTPS 提供引导脚本、固定发布元数据及一次性 CSR 注册端点；此端点不依赖尚未取得的客户端证书，也不授予浏览器/企业权限。管理员使用原有会话、同源保护和平台权限生成/撤销 15 分钟随机凭证，数据库仅保存摘要。

兑换在节点事务锁下绑定 CSR 摘要、签发证书、精确证书指纹、版本快照与审计；同 CSR 可以在有效窗口恢复同一结果，不同 CSR 不可重放。手工证书轮换/撤销也撤销旧 bootstrap 恢复权限和待激活自动轮换，不清理 applying 屏障。证书有效期 30 天；剩余 7 天时 Agent 使用本地新私钥申请证书，先持久化待激活身份，再以新证书确认激活，最后原子发布单一 identity PEM。控制端在节点锁内只允许一个待激活身份，重复请求返回同一结果，旧证书在激活提交前继续有效、提交后立即失效。

安装器使用控制台固定 SHA256 校验 GitHub 指定 tag 的 amd64/arm64 普通文件归档；不跟随 latest。私钥生成并保留在节点，注册后 systemd 启动非特权 validation 服务和定时 root updater。升级目标只能由控制端固定 Release 配置产生，节点再次验证外层摘要、平面普通文件白名单与包内摘要；升级生命周期在私有目录持久化，原子发布后同时等待目标版本心跳和同任务配置健康标记，失败恢复备份二进制。全平台单活动任务限制降低批量故障面；queued/claimed 可取消，安装开始后不可取消，rollback-failed 必须人工处理。配置、心跳、预检、续期、本地计量采样、WAL 上传和目标探测由独立 Supervisor 活动执行并分别退避；上传或探测故障不会停止本地计量，进程重启从持久 PKI/WAL/journal 恢复。每次心跳直接读取 Linux 内核资源计数；apply 模式调用现有只读组合校验器比较持久 last-good 与 nftables/tc，绝不自动修复。控制面只保存每节点最新样本和条件持续起点，固定聚合指标不暴露节点标签。只读环境报告通过现有 mTLS 精确身份通道保存；检查未知不等于可转发。控制台 UI 区分联系、资源/漂移、证书、配置、版本/升级、当前版本目标探测和健康未知。发布、真实 systemd/VPS/网络、资源压力与 PKI 运营验收仍需单独完成。

## 技术分工

| 部件 | 目标方案 |
|---|---|
| 前端 | React/Next.js |
| API、Worker | Go 模块化单体 |
| 业务与账务 | PostgreSQL，事务、唯一约束、版本与不可变账本 |
| 缓存/任务 | Redis；任务由数据库状态兜底 |
| Agent | Go，mTLS、受限权限、配置对账 |
| 数据路径 | nftables DNAT/SNAT，tc 带宽整形 |
| 可选后端 | Realm 用户态代理，独立 Adapter 和计量验证 |
| 监控 | Prometheus/Grafana、Loki、外部探针 |
| 组网扩展 | 企业 WireGuard、网络隔离、路由与 ACL |

当前为 Go HTTP + PostgreSQL + 静态页面。Node.js 只负责本地脚本。发行包中的 Go `reladock-recovery` 使用外部 age/PostgreSQL 客户端生成禁止覆盖的控制/节点加密包；控制校验只恢复到随机临时数据库，节点校验只写全新非系统暂存目录，不负责上传或状态晋升。事务 Outbox、mTLS、成员权限、规则套餐、账务和默认关闭的支付连接器已实现。Linux 显式应用 Agent 已组合 nftables/tc、WAL、内核逐规则额度/到期保护和 applied ACK；默认模式仍仅校验。React/Next.js、Redis 和企业组网尚未接入，不影响当前 PostgreSQL 事实来源。真实生产平台仍须环境与商业验收。

### 当前控制平台实现

- `cmd/reladock`：连接数据库并执行事务/advisory lock 迁移，连接失败拒绝启动；默认绑定回环，生产模式要求明确 HTTPS origin 与 TLS 证书，公网明文监听被拒绝。
- `internal/platform`：企业、成员、会话、规则、端口资源、幂等请求与审计。注册与规则操作使用事务；密码采用随机盐的 PBKDF2-SHA256（600000 次），会话使用 256 位随机令牌，仅持久化 SHA256 摘要，24 小时有效，退出立即撤销。
- `internal/web`：认证、租户写授权、同源/Host 检查、定制请求头、严格 JSON、8 KiB 业务正文限制和 HTTP 超时。开发模式进程内限流，生产模式 PostgreSQL 共享限流；Cookie 为 HttpOnly、SameSite=Strict，HTTPS 下启用 Secure/HSTS。独立支付 webhook 验签原始报文，上限 256 KiB，具有独立预算。
- 端口按 `(node_id, listen_address, protocol, listen_port)` 数据库主键唯一；节点级事务锁分配 20000–60000 范围最小可用端口。TCP/UDP 可共用相同数字端口；both 同时预留，两者与规则、幂等记录、审计一起提交或回滚。
- 创建规则必须提交企业内唯一的 `Idempotency-Key`（8–128 位字母数字及 `._:-`）；相同规范化请求重放返回原规则，不同请求返回冲突。幂等记录暂不自动过期。
- 暂停保留端口；删除软删除规则并为每个 TCP/UDP allocation 建立 retirement，入队 schema-2 缺席快照。快照在 raw prerouting 安装新连接 quarantine，并保留 allocation-ID forward guard；平台只有在 applied quarantine 之后才允许领取精确清理任务。apply-only Agent 通过 mTLS 领取并确认任务，本地持久 journal 后按精确五元约束清理 conntrack，复核 quarantine 与零匹配，再持久化 proof、回报并等待 ACK；只有完整闭环才释放 allocation 并允许同一前驱的受控复用。validation-only Agent 不领取清理任务。重复暂停/删除不增加版本或审计。
- 规则期望版本从 1 开始；企业编辑名称、目标主机、目标端口或逐规则带宽时必须提交当前 `desiredVersion`，旧版本返回冲突。入口节点、传输类型和已分配端口不通过编辑迁移；活动套餐存在时编辑带宽不得超过其版本上限。编辑、版本递增、完整配置快照与 `rule.update` 审计原子提交。仅 applied 回报推进生效版本与 applied_status，校验不推进。节点 generation 与规则版本分开。applied 不代表端到端健康，页面不得显示运行中；无虚构充值、流量或余额。
- 审计记录账户注册/登录/退出与规则创建/编辑/暂停/删除，查询仅返回本企业最近 50 条；尚未提供独立防篡改审计存储。
- 注册只创建 owner。邀请仅生成 admin/viewer；角色变化撤销旧会话和 Key。Key 仅保存摘要，按 read/write 范围与当前数据库角色复核，不具备平台权限。每直接连接 IP 每分钟 120 次 API，认证预算 10 次；不信任代理转发头。
- 数据库使用项目独立容器与数据卷，仅映射 `127.0.0.1:55434`。集成测试建立随机 schema 并清理自身数据，不清空业务表。旧 JSON 不自动导入，因为缺少可信租户归属。

### 节点配置交付（v2）

平台后台与运维 CLI 管理全局节点、维护标志、精确证书摘要与人工重试；普通企业账号只读节点元数据。节点维护只拒绝新规则预留，不隐含暂停既有规则。`node_operator_events` 保留历史运维记录，v3 新操作写入 `platform_audit_logs`；企业审计仍只返回本企业。

迁移 v26 为节点和不可变套餐价格版本增加共同的 `resource_mode`。节点模式为 `shared`、`dedicated-tenant` 或 `dedicated-rule`；后两者必须绑定 `dedicated_tenant_id`，共享模式禁止保存归属企业。规则创建先取得现有节点 advisory lock，再校验租户归属；规则专属节点在同一锁内统计未删除规则，因此并发创建也只能成功一条。存在未删除规则时，平台后台禁止更改节点模式或归属企业。租户节点目录只返回共享节点及本企业专属节点，不返回其他企业专属节点或归属 ID；Agent/内部全量节点查询保持不变。该模型只约束人工登记的资源，不调用云厂商 API。

迁移 v27 增加 `line_offerings`，每条线路商品不可变地绑定一台具体节点，并具有草稿、已发布、暂停、售罄和退役销售状态；退役为终态。新套餐价格版本必须引用线路商品，资源模式从绑定节点派生。为保留历史账务证据，旧价格版本的 `offering_id` 允许为空，但此类版本不进入客户目录且不可新购。客户目录必须提供一条自有规则，只返回绑定规则实际节点且已发布的线路。销售许可与交付状态分离：`unprovisioned` 和 `ready` 节点允许发布及购买，`maintenance`、`draining` 和 `retired` 节点禁止新销售且不进入客户目录。购买事务仍在钱包、账本和订阅写入前锁定线路并复核线路状态、节点身份及销售许可，避免旧目录或管理员并发变更造成已扣款的陈旧结果。付款成功时立即建立并开始套餐周期；若节点尚未部署，配置请求继续等待 Agent 交付，购买事务绝不修改节点状态或把付款当作就绪、应用确认和端到端健康。线路状态变更和平台审计同事务提交。

迁移 v28 使线路商品的来源市场与目标市场可为空，并增加最多 500 字的内部备注。草稿删除先取得线路排他行锁、复核期望修订和草稿状态，再用锁后的新语句检查 `plan_price_versions` 引用；这避免与持有共享线路锁的并发套餐创建发生旧快照误判。只有无引用草稿可删除，删除和 `offering.delete` 平台审计同事务提交。管理端创建、状态切换和删除均通过页面内对话框，接口失败保留在当前对话框中。

迁移 v29 将套餐代码约束放宽为小写字母或数字开头，线路商品代码仍保持字母开头。管理端以十进制美元输入价格，在请求边界舍入并转换为整数美分，数据库、钱包和账本继续只使用整数美分。省略版本或传入零时，创建事务按套餐代码取得 advisory lock，读取当前最高版本：完全相同的最新请求返回原记录，价格或其他不可变字段变化时分配下一版本；显式正版本继续用于兼容既有调用。`UNIQUE(code,version)` 仍是最终数据库约束。

平台后台的节点列表可见性由 `platform_node_visibility` 单独保存。隐藏/恢复只改变默认管理列表的展示，所有客户规则、Agent、配置交付、转发、计量、扣费、告警和 retirement 状态继续正常存在并可被相应流程读取。该表使用独立 `visibilityRevision` 做并发保护，避免为了界面整理递增节点运行 `revision`、使已经签发的排空证明或其他节点操作意外失效；每次实际变化与 `node.hide`/`node.unhide` 平台审计在同一事务提交。

节点登记撤销是安全退役之外的窄例外：仅 `unprovisioned`、从未签发证书或收到 Agent 事实、没有任何规则/端口/交付尝试/升级/退役/成本/事件/探测/计量历史，且只有自动创建的 generation-1 未领取配置的空节点可撤销。未兑换的短期安装凭证随节点在同一事务中删除；已兑换凭证会阻止撤销。服务端在节点锁下按修订号重新核验，先删除允许的初始依赖，再删除节点并写平台审计；审计失败全部回滚。节点 ID 只有完成这条未部署撤销路径后才可重新登记；重新登记的 revision 从保留审计中的历史最大值继续递增，旧页面请求不能作用于同 ID 的新登记实例。

其他节点的最终退役采用不可逆的 `maintenance -> draining -> retired` 状态机。进入 draining 会撤销安装凭证并禁止新建/恢复规则、升级和普通节点修改，但仍允许删除规则、配置重试、Agent 联系与必要的证书轮换，以便完成排空。最终退役要求规则、allocation、未释放 retirement、活动配置与升级均为空，desired/applied generation 一致，并取得与当前证书、内核 boot ID、Agent 启动时间、版本、journal sequence、last-good 摘要及完整 reusable quarantine 集合绑定的短时 mTLS attestation。心跳身份变化会消费旧证明；最终事务再次锁定节点并重算 quarantine 集合后才撤销节点身份。节点、审计、历史 retirement 与 quarantine 证据保留，不提供强制释放捷径。

`config_outbox` 保存不可变 payload、SHA256 checksum、generation、状态、尝试次数与租约。创建/编辑/暂停/恢复/删除规则时，先获取节点事务锁，再更新规则/端口、生成完整快照、写审计，全部原子提交；创建还先获取企业幂等锁，编辑还锁定规则并比较 `desiredVersion`。快照包括节点全部未删除规则及企业标识，暂停规则明确标识，删除通过完整期望集合中缺失表达。当前 payload 上限 2 MiB，历史快照暂不清理。

Agent 领取最新 generation，领取租约 60 秒，最多 5 次。应用前以同一 token/checksum 调用 begin；节点锁与唯一 applying 索引串行化。applying 不因租约过期自动清除，防止旧执行者尚未停止时新任务进入。规则变更可以排队，但 Claim 不绕过应用屏障。陈旧 applied 仅记录其实际版本，不能确认较新删除。失败只能在独立本地 Stable 核对后终结；未知结果保留 Agent journal 和平台屏障。丢失状态或轮换后无法恢复凭据须人工核对，不能通过超时或随意 SQL 清屏障。

可选 Agent HTTPS 服务单独监听 `127.0.0.1:3002`，要求 TLS 1.3 与客户端 CA 验证。证书 URI 必须是 `spiffe://reladock/nodes/<id>`，每次请求验证登记摘要，领取/回报事务在节点锁下再次检查摘要，防止轮换期间旧身份继续操作。浏览器 Cookie 不授予 Agent 权限。生产启用 Agent 监听时必须配置在线专用中间签发器；固定 Release 元数据仍可独立关闭。开发 CA/私钥不自动分发或启用，未设置 `AGENT_TLS_DIR` 时不监听该端口。

默认 Go Agent 校验快照并报告 validated/failed，不执行网络。显式应用模式在同一跨进程数据面锁中：持久候选 → 冻结平台 relay 链 → 最终 counter 落盘 → 按固定周期基线＋跨 epoch 本地实际用量重建额度 → 受控 tc → nft 原子替换/回读 → 新物理 incarnation/WAL → 最后有效状态 → applied ACK。回滚也先采样并创建独立 incarnation；不能用 generation 代替物理计数代次。已确认报告才从 WAL 清理，ACK 不清除周期累计。存储满/不确定结果停止转发或保留屏障，不静默丢用量。节点 last_seen_at 仅为控制联系时间。

tc 采用每规则双向合计上限，双方必须经过同一个显式专用 egress；packet mark 把 TCP/UDP 及上下行映射到同一 HTB class，真实路由不匹配则该业务包 drop。未配置保障带宽。读取 class/filter 时优先使用 JSON，并严格兼容 iproute2 5.15 可能返回的 HTB 文本和 fw options 混合文本；兼容路径只接受已验证结构，不完整、未知、尾随或溢出的输出拒绝应用。nft quota 对每规则上下行共享，替换前用持久已用量减去剩余额度；到期用内核 timed set，即使 Agent 停止也不无限转发。冻结规则在 owned table 内按真实 drop 表达式回读确认并幂等插入，不能仅凭 comment 信任；历史重复的有效冻结由后续成功原子替换清理。30s 应用/恢复预算配合 35s 保守到期余量，可能提前最多约 35s 停止，不能销售秒级短周期。运行时拒绝 flowtable 及 GRO/GSO/TSO/LRO 绕过条件，前置网络设置由节点运维明确完成，不由 installer 修改。参阅 DATAPLANE、SHAPING 和 METERING 文档。

### 全平台权限与管理（v3）

`members.is_platform_admin` 独立于企业角色，公开注册默认 false；只通过本机 CLI 指定已有邮箱授予/撤销。变更与清除成员全部会话、平台审计同事务。登录/会话查询每次读取当前平台标志和企业状态，不依赖前端标志或旧 Cookie 内的角色。

管理 API 位于 `/api/admin/*`，使用现有同源、Host、请求头、严格 JSON、会话和限流保护。页面 `/admin` 只是静态壳，不包含敏感数据；所有管理查询与写操作在数据库重新核验平台权限。平台授权变更、管理事务和退出登录统一先获取授权事务锁，避免权限撤销竞争及 session→账户外键锁顺序反转。管理节点再获取节点锁、规则再获取行锁；普通租户写入在事务内核验企业 active 和成员权限。

节点新增/编辑/维护/证书轮换与撤销/配置重试和平台审计原子提交；运维 CLI 与网页共用节点修改逻辑。`nodes.revision` 用于旧页面冲突保护，规则变更使用 desired_version，企业登录状态使用 tenants.revision。节点有未删除规则时不能变更绑定地址，声明速率不能低于已保存规则速率；新规则也不能超过声明速率。元数据并不代表实际已应用或健康。

套餐价格版本的线路、派生资源模式、价格、额度、带宽和周期一起不可变。租户可按自有规则查询具体节点目录；购买事务持有节点锁、规则行锁和线路共享锁后，再比较规则节点、线路节点、节点销售许可与线路销售状态，任何不匹配都在钱包、账本、订阅、规则版本和 Outbox 变更之前返回冲突。允许在 `unprovisioned` 节点上付款并立即开始周期，但节点继续如实保持未部署，规则只产生等待交付的配置请求；维护、排空和退役节点拒绝新购买。一个规则的最新活动周期禁止提前替换；到期或耗尽后购买会创建用量为零的新周期，迟到报告仍按明确 `subscriptionId` 归入旧周期。多个规则可以共享节点，但不共享套餐额度、带宽或期限。Linux apply 模式继续以逐规则 nft quota/timed set 和 tc class 执行耗尽、到期与带宽边界。

平台可分页查看企业和全局规则，并操作其他企业的规则配置；平台规则操作只记录平台管理员身份，不伪装成租户成员，不改变普通租户查询范围。企业登录停用会清除其所有会话、拒绝登录与后续写入，但不自动暂停规则或保证停止现有流量。含平台管理员的企业不能停用。

`platform_audit_logs` 保存操作人、动作、资源和非敏感说明，不保存密码、会话、证书正文或私钥；审计失败回滚业务操作。平台审计最近 100 条，交付详情最近 30 条；交付接口不返回完整快照和租约令牌。尚未提供防篡改外部审计归档或生产容量验收。

## 数据模型

Tenant、Member、Node、NodePool、EndpointAllocation、RelayRule、Path、DesiredConfig、AppliedConfig、UsageEvent、UsageBucket、Plan、PriceVersion、Order、Payment、LedgerEntry、Invoice、Probe、Incident、AuditLog。组网预留 Site、Gateway、Network、Route、AccessPolicy、Link。

## 关键设计

端口按节点/监听地址/传输/端口唯一分配。配置使用版本、幂等任务和回报确认；状态区分 pending、active、failed、paused 和 deleting。并发更新使用乐观锁。Agent 只修改本平台规则与配置。

DNAT 转发一般需要 SNAT 保证回程，客户源站看到中转 IP；需要真实源 IP 时单独设计回程或应用兼容，不能默认承诺。

计量不读 NAT 首包 counter 计算全流量。内核转发和 Realm 本地代理使用不同计数路径；标识客户与规则并统计实际业务包，避免 offload 绕过。用量 event 包含 node、epoch、sequence、rule、累计上下行和时间。节点 WAL、接收 ACK、去重、计数清零处理与账本事务共同保证可对账。

钱包用 USD 整数最小单位/定点数，价格与套餐版本化。支付回调验签、金额币种检查、幂等、退款冲正和到账对账。计费边界固定，多跳对客户只计一次；上游成本单独统计。

普通 UDP 无通用连接握手，健康需要协议响应或合作探针，未知要显示未知。主备通常只恢复新连接/重连；DNS 缓存和已有 NAT/代理状态限制切换，不能承诺无感迁移。

### 后续业务与部署增量（v4–v12）

流量与带宽按用户最新指令逐规则独立配置，企业钱包只共享货币余额，不共享字节额度。`billing_usage_reports` 与 epoch 保存累计计数、sequence 和去重事实，付费报告必须绑定 `subscriptionId`，周期归属不依赖接收时间。`subscription_usage` 汇总指定周期的实际报告；重复事件不再次扣减，迟到旧周期流量不会扣新周期额度。旧版本中无法归属的付费用量必须先对账，v10 拒绝静默清零或猜测归属。

企业展示查询从 `billing_usage_totals` 读取逐规则累计值；最近速率只在同一 epoch 的最近两个已接收报告间隔为 1–60 秒且最新报告不超过 30 秒时计算，并以有界、饱和的显示算术输出字节/秒和相对规则带宽上限的 basis points。1 小时、24 小时和 7 天趋势分别按 60、900、7200 秒，以 `billing_usage_reports.received_at` 汇总不可变增量；缺失桶不补零。接收时间速率和趋势是运营显示事实，不参与套餐周期归属、扣费或健康判定。租户资源视图复用 `node_resource_latest`，只返回其未删除规则关联节点的最新 CPU、内存、根磁盘、conntrack、时钟与数据面一致性结果；控制端不保留长期节点资源时序。

钱包采用 USD 整数美分、行锁及不可变账本；套餐价格版本不可变。购买绑定企业自己的规则、价格版本与幂等键，扣费/周期/规则带宽/Outbox/审计同事务。配额耗尽与到期只请求暂停配置，实际停止仍取决于 Agent。无预置套餐；无有效套餐的规则可以保留端口草稿，但快照中的状态保持 paused。v11 重建所有节点的最新快照以收紧旧版本行为。

开发联调例外由控制服务的显式开关写入版本化、带摘要的节点快照 `developmentBypass`，而不是修改账本或伪造套餐。Agent 仅对带该标记的 `pending-agent` 规则放宽付费周期、quota 与内核到期校验，继续逐规则计量并以空周期上报；人工暂停/删除和数据面安全门禁保持有效。默认关闭时仍严格执行上述套餐授权模型。

Stripe 是可选连接器，不是已选定或启用的生产渠道。全部配置缺失时禁用，部分配置拒绝启动。Checkout 先持久化本地幂等订单；只有验签回调、已支付状态、金额/币种/订单元数据和会话绑定全部匹配才创建到账账本。重复事件不重复到账；异常/无法自动冲正的退款及争议事件持久记录待人工复核，并冻结后续钱包支出，不能伪造处理成功或自动解除冻结。参见 PAYMENTS.md。

企业套餐确认与资金支付在界面上分为两个步骤：确认规则和不可变价格版本后进入独立 `checkout` 页面。钱包余额路径直接调用既有 `PurchasePlan` 事务；外部渠道路径按套餐整数美分价格创建钱包充值订单，并按企业和套餐选择在浏览器会话中保存未决幂等键，跳转返回或 A-B-A 切换仍恢复原订单。退出登录、401 和企业切换清除内存选择并隔离会话记录；离开支付页会使旧异步结果失效。当前 Stripe 回调只增加钱包余额，不直接创建套餐周期，因此页面必须明确要求验签到账后再使用余额购买；未配置渠道保持禁用，不能把外部跳转或浏览器返回当作到账、扣款或套餐开通。

每 30 秒进行到期与控制通道告警对账。节点/配置事件去重，后台与企业工单隔离；联系健康和转发健康分别表达。HTTPS 运行配置、Linux 发布包与组件安装模板参见 DEPLOYMENT.md；独立 Adapter 的权限、回滚和真实 Linux 测试参见 DATAPLANE.md。

监控数据不充当财务账本。不采集业务载荷，不解密客户 TLS。企业组网按租户隔离网络、路由与权限，处理重复网段、MTU、DNS 和撤权。
