# 当前实现状态与 AI 交接

> 最后核验：2026-11-01，生产控制端版本 `0.9.6`（基线提交 `b2d74d2`），生产入口 Agent 仍为 `0.9.5`；本地功能分支已增加工作台逐规则流量与节点资源遥测。本文是实现状态入口，不替代需求与架构文档；用户最新明确指令始终优先。

## 一句话结论

RelaDock 已经是具备真实 PostgreSQL 状态、租户权限、规则交付、逐规则计量与账务、mTLS Agent、Linux nftables/tc 应用、安全升级/退役和运维后台的完整预生产实现，不是静态面板或 JSON 原型。控制端与一台入口 VPS 已部署并完成一条 TCP 转发的有限实机验收，但客户协议、UDP 端到端、容量、支付商户、离机恢复及完整生产运维尚未完成，因此不能直接宣称生产就绪。发行清单仍明确输出 `productionReady=false`。

## 状态判定规则

- **已实现**：代码已接入真实数据库或 Agent/内核路径，并有自动测试；不表示已经在生产环境验收。
- **默认关闭或需显式启用**：代码存在，但缺少完整配置时不启动，或需要运维明确选择，例如 Stripe、Prometheus、Agent 自动接入和 Linux apply。
- **已实现但待环境验收**：自动测试已覆盖核心不变量，仍需真实 VPS、网络、商户或跨故障域设施验证。
- **未实现**：仅有需求、设计或扩展位，不能在 UI、文档或交付说明中写成可用功能。

后续 AI 修改功能后必须同时更新本文件的功能矩阵、未验收项和验证记录。若状态无法由代码、测试或环境证据确认，保持“未知”或“待验收”，不要推测。

## 当前功能分支增量

本次核验时分支为 `feat/agent-reliability`。仓库还存在不属于本轮功能的未跟踪官网与部署文件，后续 AI 不得重置、覆盖或误提交。当前已提交增量包括：

- 节点管理的新增、编辑、证书、交付记录、安装命令及状态变更统一使用页面内对话框；异步旧响应不会污染新打开的节点，对修订冲突会要求基于最新节点重新确认。
- 安装命令对话框关闭时清除内存中的一次性凭证，过期命令不可复制，旧异步响应不能恢复已清除凭证。
- 仅对从未部署、没有证书/Agent/规则/端口/交付尝试/升级/退役/成本/观测/计量历史的空节点开放“撤销登记”；服务端在节点锁和事务中按 revision 重新核验，并保留平台审计。已进入生命周期的节点只能走安全退役。
- 产品原理图和系统架构图已加入 README；图中虚线能力不能当作已实现主体。
- 企业工作台的规则创建与编辑统一使用页面内对话框；编辑名称、目标主机、目标端口和逐规则带宽时按 `desiredVersion` 防止旧页面覆盖，并在同一事务写入配置快照与企业审计。入口节点、传输类型和已分配端口保持不可变，需要改变时创建替代规则。
- 企业工作台规则列表自动展示逐规则累计上下行和近期带宽；独立遥测区提供带宽利用率、1h/24h/7d 稀疏流量趋势及租户关联入口节点的最新资源样本。近期速率按平台接收时间估算，空档、样本不足与过期保持未知，不伪造零流量或健康状态。

这些增量位于当前功能分支；继续开发前先执行 `git status --short --branch` 和 `git diff`，保留用户已有修改。

## 后续 AI 接手顺序

1. 完整阅读 `AGENTS.md`、`README.md`、`docs/REQUIREMENTS.md`、`docs/ARCHITECTURE.md`、`docs/ROADMAP.md` 和本文。
2. 执行 `git status --short --branch` 与 `git diff`，确认并保留现有未提交修改；不要假定工作区干净。
3. 用代码、迁移、测试和验收证据核对任务涉及的真实状态；设计文档和路线图中的目标不能自动算作已实现。
4. 开发前明确属于控制面、Agent、数据面、账务还是环境验收，保持各层状态独立。
5. 改动关键逻辑时覆盖真实故障：并发端口、越权、幂等重放、重复支付/上报、计数重置、并发扣费、配额、回滚、未知结果与状态恢复。
6. 完成后运行 `npm test`、`npm run vet` 及任务需要的隔离/实机验收；更新本文、ROADMAP 和相关专题文档。
