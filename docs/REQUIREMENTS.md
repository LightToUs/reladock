# RelaDock 需求基线

## 已确认的定位

只做网络中转，可以中转客户 VPN/代理协议所需的 TCP/UDP 流量；不做 VPN、不提供 VPN 订阅。保留跨境 SaaS、电商、办公、游戏和企业组网需求。第一阶段优先跑通商业模型，将计费和监控同转发一并交付。AI 产品线已经移除。

## 应用级连接业务边界

2026-11-01 用户确认：RelaDock 当前业务定位为面向跨境贸易、跨境电商企业及为其服务的 ERP/SaaS 厂商提供公网应用级连接。目标是连接指定的企业公网应用，不接管客户整个网络，也不处理客户的 ERP 业务数据。

该产品线的目标客户和使用方包括跨境贸易/电商企业、ERP/SaaS 厂商，以及需要访问指定企业公网应用的海外仓、海外服务器或其他业务系统。连接方向可以是境内系统访问境外公网应用，也可以是境外系统访问境内公网 ERP/API；“回国连接”仅指后一种公网应用连接，不包含进入客户内网。

应用级连接只包含以下范围：

- 连接客户明确指定的公网 IP 或公网域名、TCP/UDP 协议和端口，不提供未限定目标的通用网络出口。
- 透传应用流量，不解密、终结、修改或代管 ERP/SaaS 应用协议、账号、订单、库存、物流及其他业务数据。
- 按每条转发规则独立配置带宽、流量额度、期限、计量与账单；提供与真实证据一致的配置交付、状态、告警和运维信息。
- 只有在真实链路与客户应用完成相应验收后，才能描述该方向的连接质量；公网目标可达、Agent applied 或节点在线均不能单独作为应用端到端健康或加速效果的结论。

应用级连接产品线明确不包含：

- 客户内网 ERP、私网 IP 或未公开目标的接入，不在客户网络部署 Connector、网关、主动反连或 NAT 穿透组件。
- 站点到站点组网、客户侧路由、网段管理、ACL、双线路策略选路或完整/轻量 SD-WAN。
- ERP 功能开发、应用集成、业务数据处理、店铺账号环境、养号或平台风控规避。
- VPN 终端用户、订阅分发、消费者客户端或未限定目标的通用代理服务。

文档中保留的内网穿透、企业组网和轻量 SD-WAN 仅是后续独立产品方向，不属于当前应用级连接的已确认需求，不得因为存在架构扩展位而自动进入实现或销售范围；如未来立项，必须由用户另行明确确认产品边界、客户、合规资源和验收标准。

## 客户使用流程

2026-10-28 用户明确：流量按每条转发规则独立计算，不合并企业下多条规则结算。单规则上下行合计；流量额度、用量扣减与相关账单必须关联规则。企业汇总仅作统计展示，不用于共享流量额度或跨规则扣减。5 TB 试点额度的具体套餐归属与价格需在套餐配置时明确，不据此自动给所有规则发放额度。

2026-10-30 用户明确：当前开发测试阶段暂不校验套餐，所有配置允许下发。该行为实现为部署侧显式、默认关闭的开发开关；只绕过套餐周期、配额和到期门槛，不伪造订阅/账本，不解除人工暂停或删除，也不取消逐规则带宽、计量、节点安全检查和 applied 确认。商业生产恢复套餐校验时关闭开关并重发节点配置。

2026-10-31 Agent 升级要求：平台只允许管理员为在线、非维护节点创建指向当前固定 Release 的兼容升级任务，浏览器不得提交版本或摘要；同一时刻全平台仅有一个活动升级。节点 updater 必须使用私有持久状态、固定下载地址、普通文件白名单与双层 SHA256，升级后同时确认新版本心跳和配置轮询健康，超时或服务失败自动恢复原二进制。安装开始后不能取消；回滚失败保持人工介入，不得清状态假装成功。升级确认不等于数据面或客户协议健康。

同日用户进一步明确：带宽也按每条转发独立设置，不设置企业共享带宽额度。移除企业页面的“试点月流量参数”“试点带宽上限”“结算币种”卡片及 overview 中的全局试点参数；单规则带宽设置继续保留。节点物理能力上限仍是节点约束，非企业共享套餐。

客户开通 → 充值或购买套餐 → 选节点 → 填目标和 TCP/UDP → 平台预留端口 → Agent 应用 → 客户获得入口 → 修改自身连接配置 → 平台计量/扣费/告警 → 续费。

客户管理自己的 VPN 用户、订阅、密钥、证书、客户端和落地。平台交付入口、带宽、配额、转发和运维。端到端证书校验不得因中转被关闭。

## 第一阶段功能

| 模块 | 必须交付 |
|---|---|
| 企业账户 | 登录、成员、角色、API Key、租户隔离 |
| 节点 | 区域、容量、能力、版本、维护与状态 |
| 转发 | TCP/UDP/两者、目标 IP/域名、端口分配、启停、删除、限速、配额 |
| 配置 | 期望/生效版本、Agent ACK、校验、回滚、审计 |
| 计费 | USD 套餐、订单、到账、钱包账本、用量扣减、账单、超额处置 |
| 计量 | 按客户/规则/节点双向统计，补传、去重和可追溯 |
| 监控 | 节点、路径、规则、目标、Agent、计量积压与余额；当前已实现节点最新 CPU/内存/根磁盘/conntrack、时钟偏差与本地 nftables/tc 漂移，路径端到端和长期时序仍需外部系统 |
| Agent 升级 | 服务端固定版本、节点单任务、归档多层校验、持久状态、两信号确认、失败自动回滚、人工恢复审计 |
| 运营 | 告警、工单、成本、客户/节点组毛利和续费 |

协议透传：HY2/TUIC/WireGuard 走 UDP；VLESS/VMess 按实际外层传输；Shadowsocks TCP/UDP；OpenVPN 按配置。IPsec/NAT-T 单独评估，不能将 ESP 当成普通端口转发。具体支持以实际互通测试为准。

## 后续企业组网需求

跨境办公室/仓库/分支/云 VPC 互联、员工远程接入、固定出口、站点与设备权限、私网地址与路由、网段重叠处理、DNS、ACL、链路监控。使用企业 WireGuard 网关等组网组件。

内网穿透列入后续独立能力：客户站点没有公网入站地址时，允许部署 RelaDock 内网网关，由网关主动向公网入口建立持久出站通道，将平台分配的 TCP/UDP 公网端口映射到租户指定的内网 IP/域名与端口。该能力必须复用租户隔离、逐规则带宽/流量/计费、配置版本与 ACK、审计、告警和到期阻断；通道断开或结果未知时不得显示“运行中”。平台不解密客户业务载荷，不终结或代管客户 VPN/代理协议。

当公网中转节点已通过客户自有 WireGuard、专线、VPC 路由或其他通道可路由到私网目标时，现有转发规则可作为前置条件下的私网转发；不得将此私网可达情形宣称为平台已实现主动内网穿透。主动反连、通道建立/重连、网关身份与撤权、私网路由/ACL、重叠网段、DNS、MTU 和健康验收尚未实现。首个版本不自动修改客户路由器、不依赖 UPnP 自动开口，不承诺 P2P NAT 打洞成功率。具体通道协议、高可用模式和计费产品待设计与订单验证后确定。

后续轻量 SD-WAN：双宽带/移动备线、多路径质量探测、主备、策略选路、滞回和集中配置。链路切换不自动意味着带宽叠加或会话无损。

公网多跳、云骨干、IEPL/IPLC 资源接入保留扩展位，按订单与采购条件实施。DDoS 首期做检测、隔离和上游防护预留，不自建清洗中心。

## 不在首期范围

VPN 订阅、VPN 终端用户管理、全协议服务端面板、自建客户端、AI 产品、全球 Anycast、自建清洗中心、复杂分销和完整 SD-WAN。
